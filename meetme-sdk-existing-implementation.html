1. Overview

MeetMe is the intercom system built into iPlus Living. It connects physical door panels (installed at building entrances) to resident Android phones via SIP-based video calling, using the Linphone SDK. The backend (PHP/Yii2) handles panel configuration, SIP account provisioning, licence management, door relay commands via MQTT, and push notification wake-up via FCM.

Web Side (iplus-living-web)

  • Panel configuration & unit mapping (admin backend)
  • SIP server settings (meet_server_setting)
  • MeetMe licence management & renewal payments
  • Door relay/unlock via MQTT broker
  • API endpoints for Android app to call
  • Cron jobs: heartbeat, MQTT queue, licence reminders

Android Side (iplus-living-android)

  • Linphone SDK 5.4.22 — full SIP stack
  • LinphoneService — persistent foreground service
  • FCM wake-up for incoming panel calls
  • Video rendering via TextureView / OpenGL
  • Door unlock REST call on panel relay
  • Outgoing calls to panels and guard units

3. SIP Account Provisioning (First-Time Setup)

Before any intercom call can happen, each resident's unit needs a SIP account registered on the SIP proxy server. This is provisioned via the MeetMe licence system.

1
Admin activates MeetMe licence for a unit (Web Backend)

Admin creates a licence in meet_me_licence_master and links it to a unit in meet_me_licence. The licence_number is AES-encrypted in DB.

2
Fermax CRM provisions SIP credentials

API calls Fermax CRM: meet-me-licence-renewal/getsubscription. CRM returns SIP credentials: grandstream_server_username, grandstream_server_password, grandstream_server_domain, licence_password.

3
Android app fetches SIP config on login

HomeFragment calls IntercomController::actionIntercomconfiguration(). API executes SP meet_server_setting_get_ver3 and meet_panel_get_list_ver3. Returns SIP URL, domain, panel list, guard list.

4
Linphone SDK registers SIP account

LinphoneManager calls core.createAuthInfo() with SIP credentials and core.addProxyConfig() with the SIP server URL. Linphone sends SIP REGISTER to sip.fermax.com.

5
FCM token sent to SIP server

FirebasePushHelper obtains FCM token → stored in LinphonePreferences → passed to SIP proxy so it can push-wake the app on an incoming call. XmlRpcHelper handles account expiry renewal via XML-RPC against the provisioning server.

4. Panel Configuration (Web Admin → API → App)

Admin Sets Up a Panel (Web Backend)

Managed via backend/controllers/IntercomController.php → actionCreate():

  • Creates record in meet_panel table with UUID panel_id
  • Maps panel to units via meet_panel_unit table
  • Configures relay names/DTMF tones: relay_1…4, dtmf_tone_1…4, main_relay, panel_mode (1=2 relays, 2=4 relays)
  • Sets SIP server settings in meet_server_setting: domain, sip_url, is_check_sip_url
  • Clears cache keys: meet_panel_{type}_{condo_id}_{unit_id} and intercomconfiguration_{condo_id}_{unit_id}

Panel Bulk Import via CSV

actionPanelSettingsImport() → calls SP intercom_panel_settings_import with XML payload. CSV columns: Panel Name, Unit Number, Extension/Licence Number, Default Display Name.

5. Incoming Call Flow (Panel → Resident Phone)

A visitor presses the door panel button. This is the full sequence from panel to resident screen.

1
Panel sends SIP INVITE

The door panel (a SIP User Agent) dials the resident's SIP address (derived from licence_number). SIP INVITE is sent to SIP proxy at sip.fermax.com.

2
SIP Proxy looks up FCM token

Proxy finds the resident's registered SIP account and retrieves the FCM token that was registered by FirebasePushHelper at login.

3
FCM push delivered to Android device

MyFirebaseMessagingService.onMessageReceived() receives the push. It detects the isfromfermax flag and routes to MeetMe's own FirebaseMessagingService.

4
LinphoneService starts / wakes up

If LinphoneService is not running, it is started with a PushNotification intent. core.ensureRegistered() re-registers the SIP account so the INVITE can be received.

5
Linphone Core receives SIP INVITE

CoreListenerStub.onCallStateChanged() fires with state Call.State.IncomingReceived. NotificationsManager shows a call notification or launches CallIncomingActivity.

6
Resident sees incoming call screen

CallIncomingActivity displays the panel's display name, a video preview, and Accept / Decline buttons.

7
Resident accepts → call.accept()

Linphone sends SIP 200 OK → SIP ACK from panel. Call state moves to Connected then StreamsRunning. RTP audio and video streams begin flowing.

8
CallActivity opens with live video

Video surfaces are attached to Linphone Core via setNativeVideoWindowId(). Panel's video renders on screen. Audio routes to speaker. Resident can now speak to visitor and see them.

9
Resident declines → call.terminate()

Linphone sends SIP 486 Busy / 603 Decline. Call ends. Logged in HistoryFragment. NotificationBroadcastReceiver also handles decline from notification action button.

6. Outgoing Call Flow (Resident → Panel / Guard)

Resident initiates a call to a door panel or guard from the app.

1
HomeFragment displays panel / guard list

Data from actionIntercomconfiguration() populates PanelGuardListAdapter. Two tabs: Panel (type 1) and Guard (type 2).

2
User taps a panel

Adapter calls LinphoneActivity.instance().setAddresGoToDialerAndCall(licence_number, display_name). Flurry event logged: FLURRY_EVENT_INTERCOM_MAKE_CALL_PANEL or FLURRY_EVENT_INTERCOM_MAKE_CALL_GUARD.

3
CallManager.inviteAddress()

Creates CallParams from Core. BandwidthManager.updateWithProfileSettings() decides if video is possible. Sets recordFile path. Calls core.inviteAddressWithParams(address, params).

CallParams params = lc.createCallParams(null);
getBandwidthManager().updateWithProfileSettings(params);
params.setVideoEnabled(videoEnabled && params.isVideoEnabled());
params.setRecordFile(recordFile);
lc.inviteAddressWithParams(lAddress, params);
4
SIP INVITE sent to SIP proxy → Panel rings

CallOutgoingActivity shows a ringing screen while state is OutgoingRinging. Resident can cancel at this point via call.terminate().

5
Panel answers → StreamsRunning

State moves to Connected → StreamsRunning. CallActivity opens with live two-way video and audio to the panel.

7. Door Unlock / Relay Command Flow

During an active call, the resident taps the unlock button. The door relay is triggered via a chain: App → API → MQTT Broker → Panel.

1
App fetches relay config

Android calls IntercomController::actionPanelrelay(panel_number, condoId). API queries meet_panel table directly via meetPanelRelayData() and returns relay names, DTMF tones, panel mode.

2
Resident selects relay (unlock button)

App shows relay options (up to 4 relays in 4-relay mode, 2 in 2-relay mode). Resident taps the desired unlock button.

3
App sends unlock request to API

REST POST to iPlus API with selected relay and panel info.

4
API builds MQTT payload and calls MQTT broker

CommonComponent::callMqtt() POSTs the unlock command to MQTT broker at http://3.0.204.184/data/mqtt-app/mqtt. MQTT action: remoteOpen. The request is also queued in meet_fr_mqtt_call table for retry tracking.

$post_url = "http://3.0.204.184/data/mqtt-app/mqtt";
// MQTT payload includes: topic, panel_id, relay selection, dtmf_tone
// mqtt_action = 'remoteOpen'
CommonComponent->callMqtt($params);
5
MQTT broker delivers to panel

Broker publishes on the panel's MQTT topic. Panel receives the remoteOpen command, activates the selected relay, and the door/gate opens.

6
Response logged

Panel publishes a response on its MQTT response topic. Cron actionMqttrequest() processes the response and stores it in meet_fr_mqtt_call_response table. request_attempt counter tracks retries.

8. Video Stream – Setup & Rendering

Once the call reaches State.StreamsRunning, video is set up entirely on the Android side by Linphone SDK.

Stream Setup Sequence

1
CallActivity detects video is enabled

Checks isVideoEnabled(call) → inflates CallVideoFragment.

2
Renderer selected by GPU capability

If hasCrappyOpengl() → LinphoneTextureViewOverlay (software). Otherwise → LinphoneGL2JNIViewOverlay with AndroidVideoWindowImpl (OpenGL ES 2.0 hardware).

3
Surfaces bound to Linphone Core 
LinphoneManager.getLc().setNativeVideoWindowId(mVideoView);    // panel video → screen
LinphoneManager.getLc().setNativePreviewWindowId(mCaptureView); // local camera preview
4
Video dimensions read from negotiated CallParams 
callParams.getReceivedVideoDefinition().getWidth() / getHeight()
callParams.getSentVideoDefinition().getWidth() / getHeight()
5
Audio routed to speaker + gesture support enabled

enableSpeakerNew(true, call) forces loudspeaker. Touch listeners on mVideoView enable pinch-to-zoom (call.zoom(factor, x, y)) and scroll-to-pan.

Incoming (Panel → Phone)

  • Panel encodes → RTP packets over SIP proxy
  • Linphone C native layer decodes frames
  • Frames pushed to TextureView or OpenGL surface
  • Pinch-to-zoom via call.zoom()

Outgoing (Phone Camera → Panel)

  • Camera selected: setVideoDevice()
  • Linphone encodes → RTP to panel
  • Local preview via setNativePreviewWindowId()
  • Camera switch mid-call: CallManager.updateCall()

Video State Changes

9. MeetMe Licence Management

Each unit requires an active MeetMe licence to make/receive intercom calls. Licences are managed via the web portal and Fermax CRM.

Licence Types

TypeMeaningAction
1No licence (new)Resident must subscribe and pay
2Active (renewal eligible)Resident can renew before expiry
3ExpiredCalls disabled until renewed

Licence Renewal Flow (Web Frontend)

1
Resident opens renewal page

MeetmelicencerenewalController::actionMeetMeLicenecePayOrRenewal() loads licence from meet_me_licence_master and fetches subscription details from Fermax CRM (meet-me-licence-renewal/getsubscription).

2
Resident selects payment method and pays

Supports: Stripe (card), PayNow via OCBC QR (OCBCpayment::getQr()), DBS rewards points (iliving_admin_api/dbs/convertdbspoint), DBS PayLah.

3
Payment submitted to Fermax CRM

actionAddtransaction() POSTs to CRM: meet-me-licence-renewal/paymentofmeetlicencerenewal. On success, sends push notification (activity_type=3, ref_table=104).

4
CRM updates licence + syncs back

Fermax CRM extends expiry_date in its system. API syncs via actionMeetmecallrecieveaction() → SP meet_me_call_recieve_action → calls CRM externalsync/synclicencestatusfromiplus.

5
Receipt generated and emailed

actionPaymentdetail() → generateReceipt(TransactionID) creates PDF via mPDF. Email sent to resident.

Receive Calls Toggle

Residents can disable incoming intercom calls via actionMeetmecallrecieveaction(recieve_calls=0/1). Stored in meet_me_licence.recieve_calls. Synced to CRM immediately.

10. MQTT Communication & Panel Heartbeat

MQTT Actions

ActionTriggerWhat Happens
remoteOpenResident taps unlock during callPanel activates selected relay → door opens
syncFaceCron / admin actionPanel syncs face recognition data for authorised residents
deleteFaceAdmin removes resident accessPanel deletes resident's face from recognition DB
clearFaceAdmin bulk actionPanel clears all face recognition data

MQTT Request Queue (meet_fr_mqtt_call)

  • Every MQTT command is queued in meet_fr_mqtt_call before sending
  • request_attempt tracks retry count
  • Cron actionMqttrequest() processes 50 requests per run, 100ms sleep between each
  • Responses stored in meet_fr_mqtt_call_response

Panel Heartbeat Monitoring

Panels publish a heartbeat over MQTT periodically. The web backend monitors this:

  • Heartbeat stops: Cron actionHeartbeat() → SP meet_heart_beat_stop_email → sends admin email alert. notified = 1 set in meet_fr_mqtt_device_response.
  • Heartbeat resumes: Cron actionHeartbeatrestart() → SP meet_heart_beat_start_email → sends admin recovery email. restart_notified = 1 set.
