Visitor Pin / QR Code — How It Works

How residents issue visitor passes with a QR code or numeric PIN, how visitors are notified, and how security guards (and optionally ME/Hikvision FR doors) validate them.

Overview

What is the Visitor Pin / QR Code Feature?

The Visitor Pin / QR Code feature lets a resident pre-register an expected visitor and generate a QR code and/or numeric PIN for them. The visitor receives this code by email, and on arrival, security guards scan/enter it in the iplus app to verify the visitor is expected, log their entry, and (depending on condo configuration) automatically grant them physical door access.

Despite the "one-time" name, the code is not single-use — it remains valid for a configured time window (pass_valid_starttime → pass_valid_endtime) and can be scanned multiple times within it (e.g. entry + exit, or a group of visitors sharing one pass).

📱

Per-condo QR or PIN mode

Each condo has independent visitor_qr_code and visitor_pin flags — a condo can offer a scannable QR image, a numeric PIN, or both.

✉️

Email delivery

The QR image (uploaded to S3) and/or PIN are sent to the visitor's email via a queued mail job, using one of several templates depending on condo features.

👥

Group passes

is_group_pass + max_visitor let one QR/PIN cover multiple people (e.g. a contractor crew or event guests), tracked via a running visit count.

🔌

Optional hardware tie-in

If Hikvision/ME FR door access is enabled and the pass grants allow_unit_access, the same code is synced to hikvision_me_face_photo for use at a physical door keypad/panel.

Naming Note

"One-time" refers to the pass being issued once per visit/booking, not to single-use enforcement. Validation (visitor_qrcode_detail_ver4) only checks that the current time falls within pass_valid_starttime/pass_valid_endtime — there is no flag that marks a code as "consumed". For group passes, exceeding max_visitor only triggers an informational message to the guard, not a hard block.

Actors

Who is Involved?

🏠

Resident

Creates the visitor pass via the app — enters visitor details, validity window, and (optionally) vehicle/group info. Receives a notification when the visitor checks in.

📧

Visitor

Receives an email containing the QR code image and/or numeric PIN, and presents it (on a phone or printed) at the gate/lobby.

🛡️

Security Guard

Scans the QR (camera) or enters the PIN in the iplus app, sees pass validity + visitor details, and logs the check-in (and later check-out).

🏢

Property Management

Configures per-condo visitor_qr_code / visitor_pin flags, location/purpose lookups, and Hikvision/ME FR integration settings.

🚪

ME/Hikvision FR Door (optional)

If enabled, the visitor's PIN/QR is synced to hikvision_me_face_photo so it can be entered on a physical door keypad — reusing the ME Platform/Hikvision FR pipeline.

📋

Visit Log

unit_visitor_log records every check-in/check-out against the pass, used to compute the running visitor count for group passes.

Resident creates a visitor pass

QR / PIN / hex code generated
The pass record is created and a unique code set is generated for it.

Generates: qr_code, qr_number, hex_code, me_code, v_pin_to_me (5-digit PIN)
Inserted into: unit_visitor_pass — incl. is_group_pass, max_visitor, status, pass_valid_starttime, pass_valid_endtime
4
QR image rendered & uploaded
A scannable QR code image is generated from the code and stored for emailing.
Library: _qrcodegenerator_library($condoId, $orgqrcodename)
Storage: uploaded to AWS S3 — apiver6/controllers/VisitorController.php:771-781
5
Visitor receives the pass by email
A queued email is sent to the visitor with the QR image and/or PIN, using a template selected by condo configuration.
Sent via: Mail::addMailToQueue($toEmail, $module, $mailData, $attachment) — VisitorController.php:1573 / 1627
Templates: addvisitorpass (default), addvisitorpass_with_vehicle (Hikvision + vehicle), addvisitorpassface (face-photo enrollment + unit access)
Mail data includes: qrCode (S3 URL), qr_number, hex_number, me_code, pin_to_me, visitor_pin flag, location, unit/condo names
6
Optional: synced to Hikvision/ME FR for door access
If the condo has Hikvision/ME face-recognition doors enabled and the pass grants unit access, the code is also pushed into the FR sync table.
Condition: allow_unit_access > 0 AND is_hikvision_enable > 0 AND (visitor_qr_code OR visitor_pin)
Table: hikvision_me_face_photo — stores pin_code, person_id, me_code, visitor_pin, common_access_group_id, group_controller_template_id, type (2=QR, 3=PIN)
File: sp_change/visitor_pass_add_ver5.sql:1111-1196; sync pipeline shared with ME Platform — see sync_hikvision_me_face_new_ver4.sql:35,160-171
7
Security guard scans/enters the code on arrival
The guard's app validates the code against the pass and shows visitor details + pass validity.
API: POST /apiver6/visitor/visitorlogpassdetail (params: condoId, unitId, qrCode)
File: VisitorController.php:1115-1186 → SP visitor_qrcode_detail_ver4
Result codes: 404 not found, 202 wrong condo, 201 outside validity window, 200 valid (1001 = valid + extra-visitor info message)
Validity check: UTC_TIMESTAMP() BETWEEN pass_valid_starttime AND pass_valid_endtime
8
Check-in is logged
A visit log entry is created against the pass, and the resident is notified.
API: POST /apiver6/visitor/addvisitorlog — VisitorController.php:144 → SP visitor_log_add_ver3
Inserts into: unit_visitor_log (visitor_pass_id, is_notification_sent, is_deleted, log_type) — sp_change/visitor_log_add_ver3.sql:75-111

9
Group pass: visit count tracked
For group passes, each scan adds to a running count which is shown to the guard against the configured maximum.
log_count = COUNT(unit_visitor_log WHERE visitor_pass_id = ...) + 1
Compared against max_visitor — exceeding it shows an informational message (_getMessageForVisitorGetDetail('1002', max_visitor, log_count), :1156) but does not block entry
10
Check-out & pass cancellation
A visitor's exit can be recorded, and a pass can be cancelled before/after use.
Checkout: POST /apiver6/visitor/addouttimevisitorlog — VisitorController.php:969
Cancel/delete: POST /apiver6/visitor/deletevisitor — VisitorController.php:430 → SP visitor_delete_ver3 (soft-delete via is_deleted on unit_visitor_log)
Edit pass: POST /apiver6/visitor/updatevisitorpass — VisitorController.php:590 → SP visitors_update_ver5

Sent on pass creation with the QR image (S3 link), PIN, hex/QR numbers, location, and unit/condo details. Template varies by condo features (addvisitorpass, addvisitorpass_with_vehicle, addvisitorpassface).

🔔

Resident — Visitor Checked In

Security

Security & Operational Notes

Time-Window Validation Only

The code's "validity" is purely a time-range check (pass_valid_starttime/endtime) plus condo match — there is no cryptographic signing or single-use consumption flag.

Group Pass Cap is Advisory

Exceeding max_visitor on a group pass surfaces a message to the guard but does not block additional check-ins — enforcement relies on the guard's judgment.

Per-Condo Code Format

visitor_qr_code and visitor_pin are independent flags — a condo can require both, either, or neither, affecting which fields appear in the pass email.

Hardware Path Reuses ME/Hikvision FR Pipeline

When unit access is granted, the visitor's PIN/QR is written to hikvision_me_face_photo — the same sync mechanism used for resident face recognition (see me-platform-complete-how-it-works.html). No separate hardware protocol exists for visitor codes.
